# 💡 [Insight] CORS의 이해와 로컬 파일(file://) 환경의 모듈 제한

## 1. 문제 현상 (What Happened?)
로컬 컴퓨터에서 개발 중인 `index.html` 파일을 더블클릭하여 브라우저로 열었을 때, `main.js` 파일이 로드되지 않거나 `fetch()`, `import()` 등의  구문에서 에러가 발생하며 화면이 정상적으로 동작하지 않음.

* **에러 당시의 브라우저 주소창**: `file:///C:/Users/.../index.html`
* **에러 메시지 키워드**: `CORS`, `Cross-Origin Request Blocked`, `Fetch API cannot load`

---

## 2. 원인 분석 (Why?)

### ① Cross-Origin(교차 출처)이란?
웹 브라우저는 기본적으로 보안을 위해 **SOP(Same-Origin Policy, 동일 출처 정책)**를 따릅니다.
* **Origin(출처)**이란 `프로토콜(http/https)`, `도메인(naver.com)`, `포트번호(80/443/5500)` 3가지를 합친 것을 말합니다.
* 이 3가지 중 **하나라도 다르면** 브라우저는 이를 **Cross-Origin(다른 출처)**으로 인식하고, 다른 출처의 리소스를 함부로 가져와 읽지 못하게 기본적으로 차단합니다. 이 빗장을 안전하게 열어주는 규칙이 바로 **CORS(교차 출처 리소스 공유)**입니다.

### ② `file://` 접근 방식의 치명적인 한계
브라우저 주소창이 `file://`로 시작하는 것은 웹 서버를 거친 게 아니라, 컴퓨터 내의 파일을 직접 읽은 상태입니다.
1. **출처(Origin)의 부재**: `file://` 방식은 도메인이나 포트 개념이 없기 때문에 브라우저는 이 파일의 출처를 '알 수 없음(Null)' 혹은 '안전하지 않음'으로 판단합니다.
2. **보안 리스크 차단**: 만약 `file://` 환경에서 자바스크립트(`fetch`, `import`)가 제한 없이 작동한다면, 누군가 악성 HTML 파일을 다운로드받아 실행했을 때 그 스크립트가 내 컴퓨터 내부 파일(`C:/내사진/..` 등)을 마구 읽어서 외부로 해킹해 나갈 위험이 있습니다.
3. **ES Module의 전제 조건**: 자바스크립트의 최신 모듈 시스템(`import/export`)은 설계 단계부터 **HTTP/HTTPS 프로토콜 기반의 웹 서버 환경을 전제**로 만들어졌습니다. 따라서 `file://` 환경에서는 브라우저가 모듈 로딩을 원천 차단합니다.

---

## 3. 해결 방법 (How to Fix)

가장 확실하고 간단한 해결책은 내 컴퓨터에 **가상 웹 서버**를 띄워 `http://` 주소 기반으로 접근하는 것입니다.

### 방법 A: VS Code의 `Live Server` 익스텐션 사용 (가장 추천)
1. VS Code에서 마켓플레이스(Extensions)로 이동 후 **Live Server**를 설치합니다.
2. 분석할 `index.html` 파일을 우클릭합니다.
3. **`Open with Live Server`**를 선택합니다.
4. 주소창이 `http://127.0.0` 형태로 변경되며 모든 모듈과 통신 기능이 정상 작동합니다.

### 방법 B: 개발 프레임워크 자체 서버 구동 (PHP/Node.js 등)
현재 프로젝트 환경에 맞춰 로컬 개발 서버 구동 명령어를 활용합니다.
* **CodeIgniter 4 (PHP)**: `php spark serve` 입력 후 `http://localhost:8080` 접속
* **Node.js**: `npm run dev` 또는 `vite` 등을 통해 `http://localhost:5173` 접속

---

## 4. 핵심 요약 (Takeaway)
* 프론트엔드 자바스크립트의 최신 기능(`ES Module`, `fetch`, `import`)을 로컬에서 테스트할 때는 절대 파일을 더블클릭해서 열면 안 된다.
* 항상 **로컬 웹 서버(`http://localhost:..`)** 환경을 구축하여 브라우저에게 "안전하고 명확한 출처(Origin)"를 제공해야만 CORS 및 보안 제약을 우회할 수 있다.
